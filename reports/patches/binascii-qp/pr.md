# gh-XXXXXX: Keep quoted-printable lines within 76 characters when a line ends with whitespace

`binascii.b2a_qp()` counted a space or tab before a line break as one character, and the line-end code then rewrote it as `=20` or `=09`, so lines could reach 77 or 78 characters. Both passes (the size estimate and the output loop) now insert a soft line break before such whitespace when the three-character escape would not fit, as `b2a_qp()` already did for whitespace at the end of the data. The pure-Python encoder in `quopri` gets the same rule, so both encoders give the same output for these inputs. With `istext=False`, the soft-break check no longer treats an input newline as a line end, since that newline is encoded; this fixes a 77-character line for `b2a_qp(b'a'*76 + b'\n', istext=False)`.

Notes for reviewers:

- The new C check is `linelen + 3 > MAXLINESIZE`, not `>=` as in the escape branch, so a line that already fits (73 characters plus `=20`) is unchanged. On 120,000 random inputs (all flag combinations) compared with unpatched main, `b2a_qp()` output changed only where the old output had a line over 76 characters, `a2b_qp()` of the old and new output was identical in every case, and no new output had a line over 76.
- In header mode a space is written as `_`, which is never rewritten, so only a tab triggers the new break there. The Python check sees `_` too, so it behaves the same.
- In `quopri.encode()` the text before the new soft break is written directly rather than through `write()`: `write()` would turn a second trailing space into `=20` and make that line too long again, and `b2a_qp()` leaves it as is (it is followed by `=`, so it is not at the end of a line). The Python rule also covers whitespace at the end of the data, where the Python encoder gave 78 characters for `b'a'*75 + b' '`.
- The new `test_quopri` test runs with both encoders (`withpythonimplementation`) and checks they give the same output.
- The C and Python encoders still differ on other inputs, as before this change; none of those differences is new. The main ones: the Python encoder encodes `\r` as `=0D`; it can split an `=XX` escape across a soft line break; it encodes whitespace right before a soft line break, which can still give a 78-character line (e.g. `b'a'*74 + b' bb'`); `b2a_qp()` breaks the line one column earlier when it ends with an escape; and in header mode a trailing space at the end of the data is `=20` in C but `_` in Python.
